
Your backend structure is actually quite good for a production-level student burnout detection platform. The biggest mistake teams make is creating all files first and then getting confused about implementation order.

Follow this sequence.

# Phase 1: Project Setup

### Step 1: Initialize Backend

```bash
mkdir backend
cd backend

npm init -y

npm install express mongoose cors dotenv bcryptjs jsonwebtoken nodemailer

npm install express-rate-limit helmet morgan

npm install node-cron

npm install
typescript
ts-node-dev
@types/node
@types/express
@types/bcryptjs
```

# Phase 4: Assessment Module (Daily with Streaks)

This is the core of the project.

---

### Step 10: Assessment APIs

```http
POST /initial-assessment (submit initial)
GET /initial-assessment (get initial)

POST /daily-assessment (submit daily, max 1 per day)
GET /daily-assessment/history (get daily history)
GET /daily-assessment/latest (get latest daily)
```

---

### Step 11: Assessment Flow with Streak Logic

```text
Student Submits Daily Assessment
        ↓
Check if already submitted today
        ↓
Calculate Burnout Score
        ↓
Calculate Risk Level
        ↓
Update Streak:
  - If yesterday was completed → currentStreak += 1
  - If yesterday not completed → currentStreak = 1
  - If currentStreak > longestStreak → longestStreak = currentStreak
        ↓
Save Daily Assessment
        ↓
Update User (burnout score, risk, streak info)
```

---

Example:

```text
Stress = 9
Sleep = 3
Motivation = 2
Backlog = 8
```

↓

```text
Burnout Score = 83
```

↓

```text
Risk = HIGH
```

# Phase 10: Notifications & Cron Jobs

### notification.service.ts

Triggers:

```text
Daily Assessment Reminder (if not completed by evening)
High Risk Alert
Recommendation Update
New Week Start (with streak summary)
```

---

### reminder.job.ts (Updated for Weekly Streak Summary)

Using cron.

Every Sunday at 9 AM:

```text
Send Weekly Streak Summary Email
Contains:
  - Current Streak
  - Longest Streak
  - This Week: X/Y days completed
  - Encouragement to keep going
```

Every evening at 8 PM (optional):

```text
Daily Assessment Reminder (if not yet completed today)
```

---

### trend-analysis.job.ts

Runs daily.

Checks:

```text
Has burnout increased?
```

If yes:

```text
Create Alert
```

### Recommended Development Order

```text
1. MongoDB Connection
2. Student Model (with streak fields)
3. Authentication
4. JWT Middleware
5. Initial Assessment Module
6. Daily Assessment Module (with streak logic)
7. Burnout Engine
8. Dashboard APIs (with streak data)
9. Journal Module
10. Recommendation Engine
11. Notifications
12. AI Assistant
13. Admin Panel
14. Cron Jobs (weekly streak summary)
15. Testing
16. Deployment
```

If you're building this as a final-year/project-showcase product, I would also add **exact MongoDB schemas, API endpoints, request/response formats, and collection design** before you start coding. That will save a lot of refactoring later.
